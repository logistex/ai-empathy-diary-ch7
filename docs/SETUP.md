# 사용자 설정 안내 (로그인 준비)

구글 로그인에는 환경 변수 3개가 필요하다. 아래 순서대로 **사용자가 직접** 준비한다.
만든 값은 에이전트나 채팅에 알려 주지 말고, 프로젝트 루트의 `.env` 파일에 직접 붙여 넣는다.
(`.env`는 Git에 올라가지 않는다. 이 저장소는 공개이므로 비밀 값을 문서·코드·채팅 어디에도 쓰지 않는다.)

| 환경 변수 | 무엇인가 | 만드는 곳 |
|---|---|---|
| `AUTH_SECRET` | 로그인 정보(세션)를 암호화하는 임의의 긴 문자열 | 내 컴퓨터 (1번) |
| `AUTH_GOOGLE_ID` | 구글 OAuth 클라이언트 ID | Google Cloud Console (2번) |
| `AUTH_GOOGLE_SECRET` | 구글 OAuth 클라이언트 비밀 값 | Google Cloud Console (2번) |

`DATABASE_URL`과 `OPENROUTER_API_KEY`는 이미 `.env`에 있다. 필요한 변수 이름 전체는 `.env.example`에 있다.

---

## 1. AUTH_SECRET 만들기

터미널에서 아래 둘 중 하나를 실행해 **화면에 출력되는 한 줄**을 복사한다. (파일에는 아무것도 쓰이지 않는다.)

**방법 A. Node.js (Windows·Mac 모두 가능, 추천)**

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

**방법 B. openssl (설치되어 있을 때)**

```bash
openssl rand -base64 32
```

> `npx auth secret` 명령은 쓰지 않는다. 지금 npm의 `auth` 패키지는 Auth.js가 아니라 다른 라이브러리(Better Auth)의 도구여서 이 프로젝트와 맞지 않는다.

복사한 값을 `.env`에 아래 형태로 넣는다. (이름 뒤에 `=`를 쓰고 바로 값을 붙인다. 따옴표는 필요 없다.)

```
AUTH_SECRET=여기에_복사한_값
```

> 주의: 이 값을 바꾸면 이미 로그인한 사람은 모두 로그아웃된다. 배포할 때(5단계)는 Vercel에 **같은 값 또는 새로 만든 다른 값**을 넣는다.

## 2. Google Cloud Console에서 OAuth 클라이언트 만들기

1. <https://console.cloud.google.com> 에 접속해 구글 계정으로 로그인한다.
2. 위쪽 프로젝트 선택 상자에서 **새 프로젝트**를 만든다. (이름 예: `ai-empathy-diary`) 만든 뒤 그 프로젝트를 선택한다.
3. **OAuth 동의 화면(Google Auth Platform → 브랜딩/대상)** 을 설정한다.
   - 사용자 유형(대상): **외부**
   - 앱 이름: 예) `AI 공감 다이어리`
   - 사용자 지원 이메일, 개발자 연락처 이메일: 본인 이메일
   - 범위(Scopes): 기본값(`email`, `profile`, `openid`)이면 충분하다. 따로 추가하지 않는다.
   - 게시 상태가 **테스트**이면, **테스트 사용자**에 로그인해 볼 구글 계정 이메일을 추가한다. (추가하지 않은 계정은 로그인할 수 없다.)
4. **클라이언트(사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID)** 를 만든다.
   - 애플리케이션 유형: **웹 애플리케이션**
   - 이름: 예) `ai-empathy-diary-local`
   - **승인된 자바스크립트 원본**: `http://localhost:3000`
   - **승인된 리디렉션 URI**: `http://localhost:3000/api/auth/callback/google`
   - 만들기를 누른다.
5. 화면에 **클라이언트 ID**와 **클라이언트 보안 비밀번호(비밀 값)** 가 나온다. 다음 3번에서 쓴다.
   (비밀 값은 나중에 클라이언트 상세 화면에서도 확인하거나 새로 만들 수 있다.)

> 배포 주소(Vercel)는 **5단계에서 추가**한다. 그때 같은 클라이언트의 승인된 자바스크립트 원본에 `https://<배포 주소>`를,
> 승인된 리디렉션 URI에 `https://<배포 주소>/api/auth/callback/google`을 더한다. 지금은 localhost만 넣는다.

## 3. AUTH_GOOGLE_ID, AUTH_GOOGLE_SECRET을 .env에 넣기

2번에서 얻은 두 값을 `.env`에 아래 이름으로 넣는다. (값 부분만 본인 것으로 바꾼다.)

```
AUTH_GOOGLE_ID=클라이언트_ID_값
AUTH_GOOGLE_SECRET=클라이언트_비밀_값
```

확인 방법: 값을 화면에 출력하지 말고, 세 변수 이름이 `.env`에 있는지만 직접 눈으로 확인한다.
준비가 끝나면 에이전트에게는 값이 아니라 **"준비됨"** 이라고만 알려 준다.

## 4. 준비 후 확인 (3단계 통합 때)

- 개발 서버를 다시 시작한다. (`npm run dev` — `.env`는 시작할 때만 읽는다.)
- `http://localhost:3000` 에 들어가면 로그인 화면(`/login`)으로 이동하고, "구글로 시작하기"를 누르면 구글 로그인 창이 열린다.
- 구글 로그인 창에 계정 정보를 입력하는 일은 **사용자가 직접** 한다.

## 문제가 생기면

| 증상 | 원인 | 해결 |
|---|---|---|
| `redirect_uri_mismatch` 오류 | 승인된 리디렉션 URI가 다르다 | 2번의 주소를 글자 하나까지 똑같이 넣었는지 확인한다. (`http`, `localhost`, 포트 `3000`, 끝에 `/` 없음) |
| `access_denied` / "확인되지 않은 앱" | 동의 화면이 테스트 상태인데 테스트 사용자에 없다 | 2번 3단계에서 로그인할 계정을 테스트 사용자로 추가한다. |
| 서버 오류 `MissingSecret` | `AUTH_SECRET`이 없다 | 1번을 한 뒤 개발 서버를 다시 시작한다. |
